# OctoAcme Project Management Docs

## Overview

OctoAcme follows an iterative project lifecycle: initiation validates the problem, outcomes, stakeholders, and initial risks; planning turns approved work into a prioritized, estimated backlog with acceptance criteria, milestones, dependencies, and a Definition of Done. Teams execute in small increments, track progress and blockers on a project board, and use demos to review work.

At release, teams verify acceptance criteria, CI and security checks, release notes, rollback plans, and post-deployment checks. Retrospectives after sprints, releases, or incidents capture lessons and turn them into owned action items for continuous improvement.

The Project Manager coordinates delivery, risks, dependencies, and communication; the Product Manager sets outcomes and priorities; Developers build and test the work; QA/Testing validates quality and acceptance; and Stakeholders provide input and approvals. Teams share regular status updates and keep project state in a single source of truth. They raise blockers from the team to the PM, Product Lead, and sponsor as needed, and follow the security incident runbook for security issues. Quality is built in through unit and integration tests, CI linting and security scans, smoke tests for critical flows, and manual QA when needed.
